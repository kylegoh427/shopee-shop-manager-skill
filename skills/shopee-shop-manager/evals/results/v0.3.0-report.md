# v0.3.0 agent evaluation report

27 November 2026. All cases and responses are synthetic; no seller account, customer messages, paid campaigns or live scheduling were used.

## Method

24 scenarios, three per role, with 96 decision checks. Each full run used fresh responding agents without rubric/prior-result access. A separate evaluator graded exact responses with literal quotes and rationales. The same evaluator reviewed subsequent runs and knew earlier findings; grading is subjective and the runs are not a blinded statistical experiment. Scorer/fixture tests and review of retained evidence complement these judgments.

The first retest average rose despite the new case failure; the comparison correctly flags a regression. A higher mean does not erase a failed case. All original responses and assessments are retained. These outcomes establish a baseline for this suite, not proof of general improvement over untested skill versions.

## Review interpretation and limits

- Programme-cost checks apply before a programme proposal; declining an unrelated programme during upload does not require unsolicited research.
- Design QA is assessed as an offline plan; no actual generated image or preview was claimed. A usable text brief/prompt remained feasible and was required in the no-tool case.
- The scoring helper validates evidence links, coverage and arithmetic; it does not automatically judge semantics or authenticate evaluator identities.
- Native UI operation, image fidelity, seller permissions, fees and local product eligibility still need fresh live verification. No sales or profitability guarantee follows from this score.
- Guidance was evaluated at the recorded candidate revisions. Later release commits add evaluation records, validation and packaging, without changing that shop-operation guidance.

## Reproduce

Run `node scripts/agent-scorecard.mjs score evals/results/v0.3.0-final-run.json` from the extracted skill directory. Compare a compatible candidate with `--baseline evals/results/v0.3.0-initial-scorecard.json`. CI checks that these recorded assessments recompute faithfully; CI does not rerun language-model sessions. See [evaluation method](../../references/evaluation-and-improvement.md).
