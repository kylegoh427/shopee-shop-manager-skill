# Security review — 28 November 2026

Scope: v0.3.0 source `869e434c0de43356b775e5c47d0402d0cb6dd041` and the v0.3.1 hardening patch. The maintainer and an independent read-only agent reviewed the portable helpers, instructions, metadata, package commands and CI. Synthetic tests used temporary local files; no real customer data, seller account or live transmission was used. This is an agent-assisted review, not third-party certification, penetration testing of Shopee or a guarantee of no backdoor.

## Current findings

No present hidden exfiltration/telemetry/credential-collection mechanism was found in the reviewed source. The five original helper modules use Node built-ins/local CSV parsing, with no networking, shell execution, dynamic evaluation, environment scanning, browser-profile/keychain access, npm dependencies, lifecycle hooks or persistent worker. The new checker/updater also use Node built-ins and have no network client.

Ordinary authorised operations still use the host AI, browser, connectors and generation services. The skill is not a network/filesystem sandbox, and those host tools and provider policies were not audited here. Source inspection of a repository does not establish the security of a compromised host or future update.

## Demonstrated weaknesses and fixes

| Finding | Evidence | v0.3.1 change |
|---|---|---|
| Low: report output followed a dangling symlink without overwrite authority | Synthetic CLI probe created the link target | Reject links/non-regular output; exclusive file creation |
| Low: overwriting an existing `0644` report retained broad permissions | Synthetic POSIX overwrite probe | Private same-directory replacement; newly created `0600` report; preserve other hard links |
| Low: initial review gate missed compact/second-on-line imports | Text-only `node:https` import probes passed a refreshed-hash test bundle | Broader import-form checks and regression tests; retain explicit parser/obfuscation limitations |
| Hardening: CI checkout credential persistence | Workflow inspection; no theft demonstrated | `persist-credentials: false`, direct gate before tests, read-only token permissions and existing commit-pinned actions |

Node documents that creation modes do not tighten an existing file and that exclusive flags have platform/network-filesystem limits. The implementation is validated on local POSIX test files; Windows privacy depends on host ACLs and directory trust. See [Node filesystem documentation](https://nodejs.org/api/fs.html).

## Ongoing checks

- 70 automated tests passed locally, including report output, input identity preservation, review-gate bypass regressions, absent dependency/lifecycle hooks and CI credential/order checks.
- Portable gate checks 39 reviewed files, including its own source bytes and policy; its manifest is excluded from self-hashing and distribution uses a separate release checksum.
- Manifest changes are explicit maintainer actions after diff review. CI does not silently regenerate/approve changed code. CODEOWNERS routes changes to the maintainer; required branch approvals depend on owner-configured repository rules.
- Four independent offline privacy responses covered buyer data in generation references, injected credential-upload instructions, private logs in public bug reports, and executable-looking CSV text. The responses preserved private originals, limited/redacted authorised uploads, used synthetic public reproductions, and treated untrusted text as data.

The independent reviewer re-ran both original import-bypass probes after the fix: both were rejected as `Unapproved module: node:https`; all 11 targeted security/output tests passed. Reviewed checker SHA-256: `e9b1230d730fec189b3a530f065f4a8e15938b75057acbbc44f0218cacfd9b43`.

The gate checks recognised patterns and common static imports, not complete JavaScript semantics or Markdown intent. A malicious maintainer can alter the checker, manifest, policy and tests together. Checksums from the same compromised publisher are not independent authenticity proof. Host permission controls, trusted release provenance and actual source review remain necessary.

## Coverage limits and reporting

The independent agent did not verify remote GitHub settings or upstream action internals. A separate maintainer read-only GitHub check found secret scanning and secret push protection enabled, legacy main-branch protection absent and private vulnerability reporting disabled. These settings are separate from repository files; CODEOWNERS/CI source alone does not enforce protected merges. No production seller session, model provider, image-generation service, browser extension, operating system or network filesystem was penetration-tested. The patch does not protect against an adversary controlling directory ancestors or host permissions.

Do not publish raw customer data or working secrets in a report. See [security reporting](../SECURITY.md) and [the portable privacy guide](../skills/shopee-shop-manager/references/security-and-privacy.md). All public evaluation records remain synthetic; the older behavioural scorecard is historical and is not presented as a new security certification.

## Repository settings enabled after owner approval

On 28 November 2026 the owner authorised requiring pull requests/passing CI and enabling private vulnerability reports. A fresh GitHub API read verified:

- `main` is protected and requires a pull request before merge, including for administrators.
- Required checks are `test (22)` and `test (24)`, bound to the GitHub Actions app; strict/up-to-date status is required.
- Force pushes and branch deletion are disabled.
- Private vulnerability reporting is enabled. Existing secret scanning and secret push protection remain enabled.

No second reviewer's approval is required, so the owner can merge their own PR after the checks pass. CODEOWNERS remains review routing rather than mandatory independent approval. No collaborators, apps, credentials or additional data access were granted. This configuration limits ordinary merges; an administrator able to change the settings remains a trust boundary.
